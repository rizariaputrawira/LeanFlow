# Portable workflow sources

The four core skills were moved and revised from this repository's existing `config/skills/{brainstorm,plan,execute,orchestrate}/SKILL.md` files at revision `fc21d61df750cb409a30b9d9df6645949f70cb32`.

Source repository: https://github.com/rizariaputrawira/LeanFlow

Changes in this cutover: remove core Antigravity command/tool/role requirements; keep direct execution as default except when the user requires delegation; discover optional host delegation; centralize plan format and local artifact privacy; accept exact inline plans without inventing saved artifacts; give the coordinator sole specification/shared-plan write ownership during delegated work; preserve authorization, verification, and historical-record boundaries. Explicit orchestration now reads canonical to-spec, saves a required source-grounded specification before canonical planning, then executes only the exact resulting or validated supplied plan within consent. Missing required specification writes/privacy or unresolved material design stop dependent stages; supplied plans are validated against the saved specification and current evidence, not silently replaced.

The five canonical packages are `leanflow-brainstorm`, `leanflow-plan`, `leanflow-execute`, `leanflow-orchestrate`, and `leanflow-to-spec`. The first four are the primary workflow skills; to-spec is optional for standalone planning and required as the first, saved-file stage of explicitly selected orchestration. The former `config/skills/` package tree remains retired; the pinned paths here identify historical sources, not available packages. Only to-spec is promoted from that retired collection into a fifth canonical package. Native role identities remain `leanflow-planner`, `leanflow-executor`, and `leanflow-reviewer`; roles bind host capabilities to the canonical procedures rather than maintain duplicate workflows.

Planning consolidation absorbs the former `flashplan`, `superplan`, and `hyperplan` entrypoints into `leanflow-plan`. The former flash/super aliases had no distinct implementation; the consolidated skill now defines evidence-based flash/super/hyper methods. Hyper retains the former five critique perspectives and bounded revision, without mandatory workers. Retired planning packages are removed, not retained as aliases.

This records the immediate source and changes, not an independently established upstream license lineage. No new license grant is asserted here. Existing optional adapter assets and their source notices remain separate; the portable core does not require the bundled visual companion or other adapter utilities.

`leanflow-to-spec` was restored and revised from this repository's [`config/skills/leanflow-to-spec/SKILL.md` at revision `dac4348a027ba89072509acb5bacdef363e59b0f`](https://github.com/rizariaputrawira/LeanFlow/blob/dac4348a027ba89072509acb5bacdef363e59b0f/config/skills/leanflow-to-spec/SKILL.md), recovered directly with `git show HEAD:config/skills/leanflow-to-spec/SKILL.md` while HEAD named that revision. The source preserved optional conversation/design-to-reference-spec synthesis, the relevant template and settled-decision table, non-colliding `.workflow/specs/` records, and an optional canonical planning handoff.

The canonical revision removes adapter/install assumptions, makes explicit standalone or orchestration invocation and write authorization clear, reuses `leanflow-plan` as the privacy-procedure owner, returns a complete in-chat specification when saving is unavailable, and separates actual requirements, constraints, and unknowns without inventing content. Orchestration requires the coordinator to save the specification first and read that exact file for planning; an inline draft cannot bypass a missing required save. Standalone planning remains specification-optional, and specification-only requests stop after their result. Specification writing alone does not authorize later planning, implementation, delegation, commits, or host configuration; an orchestration request supplies only its scoped, permission-limited authorization. Worker assignment packets now carry exact specification/source resolution and allow an explicit “no plan exists yet” for drafting without inventing artifacts. This is immediate repository provenance, not an independently established upstream author or license grant. Restoring this fifth package does not relabel earlier four-skill validation as five-skill evidence.

No model calls or live host installation are established by this provenance record.
