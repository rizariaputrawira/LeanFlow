# Optional visual architecture report

Read only when a visual report is requested and writing to the intended destination is permitted. This reference grants no file or browser authority. Return the report inline when read-only/planning-only restrictions prevent a separate artifact. Do not create an architecture-report directory, alternate workflow artifact, or tracked copy of private planning content by default.

Keep the report static, self-contained, and evidence-linked. Each candidate should include:

- a short deepening title and confidence;
- dependency category and inspected source paths;
- observed friction and proposed change, clearly distinguished;
- expected locality, leverage, and test consequences;
- accessible before/after schematics of module, interface, and seam relationships;
- a decision conflict only when an actual source supports one.

End with the strongest candidate and why it deserves exploration. Do not display a guessed topology as observed fact or let a diagram replace the source evidence.

Use semantic headings, readable text, sufficient contrast, and text labels or alternate descriptions so diagrams are not the sole carrier of meaning. Prefer inline CSS/SVG or plain text diagrams. Do not depend on CDNs, external scripts, remote assets containing user data, shell openers, or host-specific rendering tools. Escape untrusted source text and do not execute or embed source-derived scripts. Evidence is more valuable than decoration; the same report in chat is an equally valid outcome when no authorized file destination exists.
