# Specification template

Read before drafting a reference specification. Use only sections relevant to the source. This template is a drafting aid, not permission to invent missing content or a mandatory implementation plan.

```markdown
# <Title>

**Status:** Draft
**Source:** <conversation or source path>
**Date:** <YYYY-MM-DD>

## Problem Statement
## Requirements
## Proposed Solution
## User Stories
## Constraints
## Implementation Decisions
## Settled Decisions & Answers
| ID | Decision | Rationale |
|---|---|---|
## Testing Seams
## Open Questions & Unknowns
## Out of Scope
```

The specification structure is adapted from Matt Pocock's to-spec, with LeanFlow-specific requirements, constraints, settled decisions, and unknowns. Retained [MIT notice](../LICENSE.matt).
